# Github Issue 등록

> 작성 규칙의 원본은 `Docs/Documentation/Github Issue Rule.md`이다. 이 스킬은 절차와 멘트 규격만 정의하며, 각 단계에서 지정한 섹션을 읽고 따른다.
>
> 권유 판단 기준과 Issue 단계의 진행 조건은 `Docs/Claude/WorkflowRules.md`의 `## 2. Github Issue`를 따른다.

---

## 권유 멘트 규격

> 사용자가 명령하지 않았지만 Issue 등록이 필요하다고 판단한 경우에 사용한다. 권유만 하고 임의로 생성하지 않는다.

```
💡 Issue 등록을 권유합니다.
- 사유 : [해당되는 판단 기준 (여러 파일 변경 / 여러 단계 작업 / 다른 Issue와 연관)]
- 예상 제목 : [제목 초안]
등록할까요? (`/github-issue`)
```

---

## 등록 절차

### 1. 배경 / 목적 확인

- `Github Issue Rule.md`의 `## 2. 배경 / 목적`을 읽는다.
- 배경 / 목적을 사용자에게 질문한다. 답변이 없으면 등록을 거부하고 사유를 알린다.

### 2. 초안 작성

- `Github Issue Rule.md`의 `# 1. [Title]` ~ `## 6. 특이사항`, `## 7. 기타`의 `Label` 항목을 읽고, 섹션별 규칙에 맞춰 초안을 작성한다.
- 규칙만으로 채울 수 없는 정보(작업 대상 파일, 연관 Issue 등)는 추측하지 않고 사용자에게 질문한다.

### 3. 등록 승인 요청

> 아래 규격으로 초안 요약을 제시하고 승인을 받는다. 승인 전에는 등록하지 않는다.

```
## Issue 등록 승인 요청

**제목** : [제목] | **Label** : [Label]

**배경 / 목적**
- ...

**목표 (To-be)**
- ...

**작업 내용**
- ...

**완료조건 (DoD)**
- [ ] ...

**특이사항** : [해당 시에만 기재]

등록할까요?
```

- 사용자가 수정을 요청하면 반영한 뒤 다시 이 규격으로 제시한다.

### 4. 등록

- `gh label list`로 Label 존재 여부를 확인하고, 없으면 `gh label create`로 등록한다.
- `gh issue create`로 Issue를 등록한다.

### 5. 등록 완료 보고

```
✅ Issue 등록 완료 : #[번호] [제목]
- 링크 : [URL]
착수명령을 주시면 브리핑을 진행합니다.
```

- 등록 후 바로 작업하지 않는다. 착수명령을 받은 뒤 `WorkflowRules.md`의 `## 3. 브리핑` 단계로 진행한다.
